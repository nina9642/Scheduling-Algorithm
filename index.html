3. How to use this app

  1. Pick a workflow. Choose Class scheduling for teachers, students, and time slots, or TA scheduling for lab sections and teaching assistants.
  2. Prepare your CSV files. Each file is a simple spreadsheet saved as .csv. See sections 4 and 5 below for what each column means.
  3. Upload the files using the file pickers above, or click Load sample files to try the built-in examples first.
  4. Click Run scheduling solver. A progress bar will count through the generations (for example, 1/100, 2/100, and so on).
  5. Read the output table. The solver shows its best schedule and a score. Higher scores usually mean fewer conflicts and a more balanced assignment.

4. What is a CSV file?

A CSV (Comma-Separated Values) file is a plain-text spreadsheet. Programs like Excel, Google Sheets, and Numbers can open and save them.

Commas separate columns. Each comma marks the end of one cell and the start of the next.

Example: 1,Jason Cao,8,V0812 means four cells in one row:

  • Cell 1: 1
  • Cell 2: Jason Cao
  • Cell 3: 8
  • Cell 4: V0812
  • First row = column names. The top row tells the app what each column represents. Do not delete it.
  • One row = one record. Each line after the header is one student, teacher, class, lab, or time slot.
  • Empty cells are okay. If a value is missing, leave that spot blank. In the file this looks like two commas in a row, like 3,4,,.
  • Save as CSV, not Excel. When exporting from a spreadsheet app, choose “CSV” or “Comma Separated Values.”
  • Keep column order the same as in the examples below unless you are sure the app supports your headers.

5. How the genetic algorithm works

This app uses a genetic algorithm, a search method inspired by evolution in nature. Instead of trying every possible schedule by hand, the computer creates many candidate schedules, keeps the good ones, and improves them over time.

  1. Start with random schedules. The solver builds a large population of possible assignments (for example, which teacher gets which class, or which TA covers which lab).
  2. Score each schedule. Every candidate gets a fitness score. Schedules with overlapping assignments, unavailable people, or uneven workloads score lower.
  3. Keep the best candidates. The highest-scoring schedules are selected to “reproduce” into the next generation.
  4. Mix and mutate. The solver combines parts of good schedules and makes small random changes to explore new options.
  5. Repeat for 100 generations. Each generation tries to beat the last one. The progress bar shows where you are, such as 37/100.
  6. Return the best result found. When the run finishes, the app displays the highest-scoring schedule it discovered. It may not be perfect, but it is the best option found in the time allowed.

Because the process includes randomness, running the solver again can produce a slightly different schedule with a similar score.

6. CSV file reference and examples

Each example below shows the file name, what every column means, and a sample row with labels.

Class scheduling files

You need all six files below. Student IDs used in class files must match the IDs in Students.csv. Teacher IDs must match Teachers.csv.

Students.csv

One row per student.

  • ID — unique student number used everywhere else in your files
  • Name — student’s full name (for your records; the solver mainly uses the ID)
  • Book — skill level or book number (higher numbers usually mean more advanced)
  • Piece — optional piece code or name
ID,Name,Book,Piece 1,Jason Cao,8,V0812 2,Kaitlyn Murray,8,V0805

Row 1 above means: student ID 1, named Jason Cao, book level 8, piece V0812.

Teachers.csv

One row per teacher.

  • ID — unique teacher number
  • Name — teacher’s name
  • Book — highest book level that teacher can teach
ID,Name,Book 1,Tal,8 2,Kirsten,7

Row 1 above means: teacher ID 1, named Tal, can teach up to book level 8.

Masterclasses.csv

Small group classes with up to four students.

  • Group ID — unique class ID (appears in the output table)
  • Level — required book level for this class
  • Student 1 to Student 4 — student IDs from Students.csv; leave unused slots blank
Group ID,Level,Student 1,Student 2,Student 3,Student 4 1,8,1,2,, 2,7,3,4,,

Row 1 above means: masterclass ID 1, level 8, with students 1 and 2. The two empty commas at the end mean slots 3 and 4 are unused.

Group Class.csv

Larger shared classes defined by book levels.

  • ID — unique class ID
  • Book 1, Book 2 — book levels included in this group; leave extra columns blank if unused
ID,Book 1,Book 2 22,8,7 23,6,5

Row 1 above means: group class ID 22 covers book levels 8 and 7.

Orchestra.csv

Orchestra sections by book level.

  • ID — unique orchestra class ID
  • Book 1, Book 2, Book 3 — book levels in this orchestra; leave unused book columns blank
ID,Book 1,Book 2,Book 3 27,8,7,6 28,5,4,

Row 1 above means: orchestra ID 27 includes book levels 8, 7, and 6.

Times.csv

Available time slots during the day.

  • ID — unique time-slot number stored in the schedule
  • Time — hour label shown in the output (for example, 9 means 9:00)
ID,Time 1,9 2,10 3,11

Row 1 above means: time slot ID 1 is labeled 9 in the finished schedule.

TA scheduling files

You need both files below. Every lab in Availability.csv must appear in Lab Schedule.csv, in the same order.

Lab Schedule.csv

One row per lab section that needs a TA.

  • Lab Name — lab section code (for example, 001L)
  • Day — day of the week as a number (for example, 2 = Tuesday, 3 = Wednesday)
  • Start — lab start time in H:MM or HH:MM format
  • End — lab end time in the same format
Lab Name,Day,Start,End 001L,3,8:00,9:50 002L,3,10:00,11:50 003L,3,15:15,17:05

Row 1 above means: lab 001L meets on day 3 from 8:00 to 9:50.

Availability.csv

Shows which TAs can cover which labs. Each TA gets a column letter.

  • Lab Name — must match a lab from Lab Schedule.csv
  • A, B, C, … — one column per TA; put x if that TA is available, or leave the cell blank if not
Lab Name,A,B,C,D,E 001L,x,,x,x, 002L,x,x,,, 003L,,x,x,,

Row 1 above means: for lab 001L, TAs A, C, and D are available. The empty cells between commas mean those TAs are not available.

The finished schedule shows the lab, the assigned TA letter, and the lab time. Example output row: 001L | A | 8:00 - 9:50.
